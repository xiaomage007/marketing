## 七、关键设计决策

1. **模板方法模式**贯穿三个领域服务：`AbstractRaffleStrategy`（抽奖流程）、`AbstractRaffleActivityAccountQuota`（充值流程）、`AbstractRaffleActivityPartake`（参与流程）——抽象类固定流程骨架，子类只实现可变步骤（`buildOrderAggregate` / `doSaveOrder` / `doFilterAccount` 等）。
2. **交易策略模式（第 27 节新增）**：额度下单的第 5 步从固定 `doSaveOrder` 改为 `tradePolicyGroup.get(orderTradeType.getCode()).trade(agg)` 路由——`rebate_no_pay_trade`（返利无支付，直接充值到账）与 `credit_pay_trade`（积分兑换，落 wait_pay 单等 MQ 回调发货）两个 `@Service("code")` 实现由 Spring 按 bean 名组装成路由表，与 `IDistributeAward`（bean 名 = award_key）、`ILogicChain`（bean 名 = 规则 code）同一机制；`SkuRechargeEntity.orderTradeType` 默认 `rebate_no_pay_trade` 保证老链路零改动。
2. **规则组织二分法**：前置规则（决定抽奖方式）用**责任链**（线性、数据库配置顺序）；后置规则（对奖品的二次决策）用**决策树**（分支路由、出边数据驱动）。两者节点注册机制相同：`@Component("rule_xxx")` bean 名 = 数据库规则 code。
3. **聚合 + 单事务**：`CreateQuotaOrderAggregate`（订单+账户）、`CreatePartakeOrderAggregate`（三账户+参与单）、`UserAwardRecordAggregate`（记录+任务+核销）——一个聚合一个事务，事务边界即聚合边界。
4. **分库路由 + 编程式事务**：`dbRouter.doRouter(userId)` 保证事务内所有 SQL 走同一物理库连接；`TransactionTemplate` 替代 `@Transactional`（注解事务与 ThreadLocal 路由的兼容性差）；finally 必 `dbRouter.clear()`（线程池复用防串库）。
5. **Redis 抗写 + DB 异步刷盘**：所有库存扣减先走 Redis 原子操作（DECR + SETNX 分段锁防超卖），扣减事件经 Redisson 延迟队列（3s）缓冲，定时任务 5s/条 串行刷盘——把「防超卖」与「落库」解耦，DB 写 QPS 与抽奖峰值解耦。
6. **任务表 + 事务后发消息**：MQ 投递永不进事务；task 表记录消息与投递参数，发送失败由 Job 无限重试补偿，实现本地 DB 与 MQ 的最终一致性（至少一次投递 + 消费幂等）。
7. **幂等三层防线**：业务层（未使用订单复用）、数据库层（唯一索引 `uq_order_id`）、状态机层（update ... where state 条件更新影响行数校验，失败即回滚）。
8. **配置驱动 MQ 拓扑**：队列声明收敛到 yml 的 `rabbitmq.topology` 段，消费方用 SpEL 引用同名配置，避免硬编码队列名分散在各注解。
