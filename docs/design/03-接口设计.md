## 五、接口设计

统一前缀：`http://localhost:8091/api/v1`，响应结构 `Response<T>{code, info, data}`。

### 5.1 活动装配（数据预热）

```bash
curl --request GET \
  --url 'http://localhost:8091/api/v1/raffle/activity/armory?activityId=100301'
```

成功：`{"code":"0000","info":"成功","data":true}`

### 5.2 活动抽奖（主链路）

```bash
curl --request POST \
  --url http://localhost:8091/api/v1/raffle/activity/draw \
  --header 'content-type: application/json' \
  --data '{"userId":"Charlie","activityId":100301}'
```

成功（抽中 3 等奖）：

```json
{"code":"0000","info":"成功","data":{"awardId":106,"awardTitle":"3等奖","awardIndex":6}}
```

失败举例（额度用尽）：`{"code":"ERR_BIZ_006","info":"账户总额度不足","data":null}`

### 5.3 策略装配（策略维度）

```bash
curl --request GET \
  --url 'http://localhost:8091/api/v1/raffle/strategy_armory?strategyId=100006'
```

### 5.4 查询奖品列表（含解锁状态）

```bash
curl --request POST \
  --url http://localhost:8091/api/v1/raffle/query_raffle_award_list \
  --header 'content-type: application/json' \
  --data '{"userId":"Charlie","activityId":100301}'
```

入参为 `{userId, activityId}`（v1 旧版只用 strategyId;v2 起改为活动维度，并叠加解锁状态）。返回每个奖品的 `awardId / awardTitle / awardSubtitle / sort / awardRuleLockCount / isAwardUnlock / waitUnLockCount`，用于前端奖品栏「抽奖 N 次后解锁」角标展示。详见 §4.14。

### 5.5 查询权重规则与可解锁奖品（v1 策略维度）

```bash
curl --request POST \
  --url http://localhost:8091/api/v1/raffle/query_raffle_strategy_rule_weight \
  --header 'content-type: application/json' \
  --data '{"userId":"Charlie","activityId":100301}'
```

入参 `{userId, activityId}`，内部流程（`RaffleStrategyController.queryRaffleStrategyRuleWeight`）：

1. `queryRaffleActivityAccountPartakeCount(activityId, userId)` 拿用户**总参与次数**（`totalCount - totalCountSurplus`，未参与返回 0）；
2. `raffleRule.queryAwardRuleWeightByActivityId(activityId)` 拿策略下所有权重档位 `List<RuleWeightVO>`（`weight` + `List<Award{awardId, awardTitle}>`，来源 `strategy_rule.rule_value` 解析）；
3. 逐档位封装为 `RaffleStrategyRuleWeightResponseDTO{ruleWeightCount, userActivityAccountTotalUseCount, strategyAwards[]}`。

返回每个权重档位（如 4000/5000/6000）下当前可命中的奖品列表 + 用户已抽次数，前端可用于展示「再抽 N 次解锁更高档奖品」。

### 5.6 随机抽奖（策略维度，不经活动/账户）

```bash
curl --request POST \
  --url http://localhost:8091/api/v1/raffle/random_raffle \
  --header 'content-type: application/json' \
  --data '{"strategyId":100006}'
```

内部以 `userId="system"` 调用 `performRaffle`，适合策略调试；不创建参与单、不扣账户额度、不写中奖记录。

### 5.7 查询用户活动账户额度

```bash
curl --request POST \
  --url http://localhost:8091/api/v1/raffle/activity/query_user_activity_account \
  --header 'content-type: application/json' \
  --data '{"userId":"Charlie","activityId":100301}'
```

入参 `{userId, activityId}`，返回 `UserActivityAccountResponseDTO{totalCount, totalCountSurplus, dayCount, dayCountSurplus, monthCount, monthCountSurplus}`，用于前端展示账户剩余抽奖次数。底层调用 `IRaffleActivityAccountQuotaService.queryActivityAccountEntity`（详见 §4.4 账户模型）。

### 5.8 异常码清单（`ResponseCode`）

| code | 含义 | 典型触发点 |
|---|---|---|
| `0000` | 成功 | — |
| `0001` | 未知失败 | 兜底 catch |
| `0002` | 非法参数 | draw / queryUserActivityAccount 等入参为空 |
| `0003` | 唯一索引冲突 | 订单/记录重复落库 |
| `ERR_BIZ_001` | rule_weight 已适用但未配置 | 策略装配 |
| `ERR_BIZ_002` | 策略未装配 | 未 armory 直接抽奖 |
| `ERR_BIZ_003` | 活动未开启 | 参与下单 / 充值下单 |
| `ERR_BIZ_004` | 非活动日期范围 | 同上 |
| `ERR_BIZ_005` | 活动库存不足（SKU） | 充值下单扣库存 |
| `ERR_BIZ_006` | 账户总额度不足 | 参与下单 |
| `ERR_BIZ_007` | 账户月额度不足 | 参与下单 |
| `ERR_BIZ_008` | 账户日额度不足 | 参与下单 |
| `ERR_BIZ_009` | 抽奖单已使用过 | 中奖记录核销 |
